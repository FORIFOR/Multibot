# UI review protocol

実装者の自信や実装量ではなく、提示された画面と証拠を評価する。
まずbrief/acceptanceと画像を読み、必要に応じてコードを確認する。
画像がない、開けない、状態が不足する項目はUNVERIFIED。
画像だけからクリックの動作、アクセシビリティ適合、応答速度を断定しない。

## Return format
- 対象: 画面、画像のファイル名と領域、viewport、確認状態。
- 総評: keep / revise / blocked。競合超えを断定しない。
- 最大5件の優先指摘: P0/P1/P2、証拠、利用者への影響、最小の修正、再確認方法。
- 維持する点: 既に目的を満たしており、変更で悪化させるべきでない箇所。
- 未確認: 操作、motion、実機、別言語、その他証拠がない範囲。
- 比較を求められた場合: A/Bそれぞれの良い点と対象タスクとの適合を述べる。

P0: 主要操作が実行不能、誤送信等の重大な不一致、重大なデータ損失。
P1: 主導線が分からない、主要情報が読めない・隠れる、操作に重大な障害。
P2: 細部の整列、軽微な余白やタイポグラフィの不統一。
好みをバグとして扱わない。ブリーフに反する美的ルールを勝手に追加しない。
レビューの点数や件数のために架空の問題を作らない。
