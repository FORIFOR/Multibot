# Visual review — 静止画、操作、成果物を分けて確認する

## 証拠の準備
対象revision/差分、OS、ブラウザー/アプリ版、画面幅、zoom、言語、theme、データを記録する。
既存の証拠フォルダーを優先する。なければdocs/quality/evidence等、repoに合う保存先を決める。
比較画像は同じ環境・fixture・操作状態で撮る。時刻、乱数、animation等の変動を制御した場合は記録する。
秘密や個人情報を含まない試験データを使う。公開用デモと内部の試験ログは分ける。

## 1. First use — 操作ルートを教える前
主要タスクと起動情報だけで、入口、最小入力、処理状況、結果、修正・保存まで辿れるか試す。
迷った箇所、助言の有無、所要時間、誤操作、戻り方を残す。
AI操作はAIの探索として記録する。人間の初心者テストと置き換えない。

## 2. Visual craft — 必ず画像を開く
画像を保存しただけでレビュー済みにしない。DOMだけでも不可。
主役、読む順、まとまり、文字の階層、日本語改行、整列、余白、密度、コントラスト、素材の切抜きを見る。
一部の美しいヒーローだけでなく、結果、失敗、長文、狭幅を確認する。
「AIっぽい」で止めず「全情報が同じカードに入り主結果が埋もれる」など修正可能な観測を書く。
同じブランドの既存画面と並べ、部品や余白の揺れと、意図ある違いを区別する。

## 3. Interaction craft — 操作/録画
入力、切替、待機、取消、失敗、復帰、保存を実際に行う。
動きは読みやすさを助けるか、完了待ちを増やすか、中断可能かを確認する。
キーボード、日本語IME、長文、フォーカス移動、200%拡大、touch、reduced motionを対象に合わせて試す。
スクリーンリーダーなど必要な手動試験を、自動a11yの成功だけで合格にしない。

## 4. Result and engineering
クリック後の見た目だけでなく成果物/永続化/必要な外部結果を照合する。
console、network、build、typecheck、test、必要なE2E/性能試験を確認する。
外部実行は承認済みsandbox/試験アカウントを使い、無許可の発信・投稿・課金をしない。
画面差分試験は視覚退行の検出であり、美的品質の証明ではない。
壊れた画面に合わせてbaselineを更新しない。承認されたデザイン変更だけ理由付きで更新する。

## 比較表
各項目を観測できる欠陥と修正につなぐ。平均点で致命的な問題を隠さない。

| 軸 | 確かめること | 適する証拠 |
|---|---|---|
| 理解 | 何ができ、次に何をするか分かる | 初見操作の経路・迷い・助言 |
| 造形 | 階層・余白・文字・素材・製品らしさ | 同条件の画像と具体的な指摘 |
| 操作 | 入力・状態・取消・復帰が一貫 | 操作録画・trace・状態記録 |
| 成果 | 実際の成果物を得て使える | 保存/編集/出力の照合 |
| 多様な利用 | 日本語・狭幅・支援技術で成立 | 対象環境ごとの手動/自動試験 |
| 性能 | 合意した予算を満たす | ラボ/実利用を区別した計測 |

## 判定と修正
PASS / FAIL / BLOCKED / NOT_APPLICABLEを使い、根拠を添える。
P0: 無承認の作用、情報漏えい、データ消失など重大な問題。
P1: 主タスク未成立、主要操作が発見不能、対象幅で操作不能、合意した主画面の未実装。
P2: 個別の整列、余白、微妙な折返し等。ただし積み重なって主タスクを妨げるならP1。
純粋な好みはsuggestionとして分け、普遍的な欠陥と断定しない。

各指摘に、画面/状態、expected、observed、再現手順、証拠、修正案を付ける。
実装者が修正→同条件で再確認。最大3ラウンドを目安に未達と再開条件を残す。
全合格になるまで無限に続けず、未確認を消して終わらせることもしない。
