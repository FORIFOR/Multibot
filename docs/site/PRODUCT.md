# PRODUCT.md — Agent Team (repository: FORIFOR/Multibot)

## 名前
- 製品名: **Agent Team**。リポジトリ名は **Multibot**（FORIFOR/Multibot）。サイト・README・OG・SNS では「Agent Team（GitHub: FORIFOR/Multibot）」と併記し、片方だけを使わない。
- ライセンス: MIT。サイトのヘッダとフッタに表示する。

## 一文の価値
資料やコードの作成を、レビューまで任せる。AI チーム（Master / Researcher / Builder / Reviewer）が実メッセージで作成・レビュー・修正を進め、成果物と検証の経緯を同じ実行記録に残す。

## 誰のための何か
- 主対象: AI に仕事を任せたいが、監査できない成果には署名しない開発者・技術リーダー。
- 副対象: 自社の作業フロー（調査 → 作成 → レビュー → 修正）を AI チーム化したい事業側。

## 見せるべきもの（優先順）
2026-09-19 改訂: 最初に見せるのは、製品と同じキャラクターのチームと3ステップの流れ。実成果物は「実際の記録」で記録原文を見せ、以下の 1〜7 はアプリ本体の画面の優先順として残す。
1. **チャット中心の実行画面**が最初に見える（Bot間メッセージ、タスク別スレッド、参加者）。
2. **実成果物**を隣で確認できる（初稿 → レビュー指摘 → 修正 → 再検証の実データ）。
3. 指摘をクリックすると、成果物の該当箇所へ移動する（この製品だけの操作）。
4. 完了・部分完了・失敗の実績を、理由と証拠ファイルつきで並べる。
5. 二つの導線: OSS（GitHub / 自己ホスト）と、事業相談（非公開チャネル）。
6. 依頼時の資料添付と、実行中の人間の指示引き継ぎをチャット中心の画面で確認できる。
7. 成果物の版間差分を確認して採用版を明示し、成果物・報告・イベントログを仕事単位で取得できる。

## 使わないもの
- 台本の会話、架空の成功ログ、意味のない光る球、実データのない小さなダッシュボード。背景の色面はヒーローと最後のCTAの淡いものに限る（2026-09-19 改訂、[DESIGN.md](DESIGN.md)）。
- ヒーローのステージは「動きの説明」であり、Bot間の会話文や成功ログを表示しない。「AIは動いていない」と明記する。
- スター数・成長率・ベンチマークの約束。
