# DESIGN.md — Agent Team site

## 方針
- 実際のソフトウェアと実行記録を、白い画面で読みやすく見せる。背景演出、勾配、浮遊カード、意味のない英語ラベルは使わない。
- ページの順序は「見出し・実例」「任せられる作業」「使い方」「業務利用の相談」「フッター」。通常のナビゲーションは実例・作業・使い方・相談・GitHub・言語切り替えに絞る。
- JavaScriptが動かなくても見出し、説明、導入条件、問い合わせへの入口を読めるようにする。実例の詳細だけはrecord.jsが描画する。

## レイアウト
- 最大幅1200px。本文17px、行間1.8。H1はPC 52〜58px、モバイル34px。セクション間隔は112px（モバイル80px）。ボタン高さ48px、角丸6px。
- 書体はIBM Plex Sans JP（英語は同系のIBM Plex Sans）に統一する。IBM Plex Monoはコマンド、時刻、ハッシュ、状態ラベルだけに使う。
- 色は背景`#FFFFFF`、薄い背景`#F5F5F3`、本文`#202020`、補足`#626262`、線`#E6E6E3`。操作と修正箇所だけ朱色`#A9462E`、合格`#2F6B3A`、未検証`#8A6200`を使う。影は使わない。
- 通常説明は見出し・文章・横線で構成し、枠は実例、コード、フォームの境界だけに使う。

## 実例
- PCは成果物2/3、進行記録1/3。モバイルは成果物→進行記録の一列にする。
- 右側のF-1〜F-3を押すと、左側の変更前・変更後の該当箇所へ移動し朱色の線が一度だけ脈動する。初期表示はF-1を選択する。`prefers-reduced-motion`では即時移動し脈動を止める。
- 実行の制約（partial、原文照合unverified）は実例の直下に置き、原因の詳細はリポジトリへリンクする。
- 動画はdetailsの中で手動再生する。`real-walkthrough-ja-silent.mp4`は既存の実行画面から音声を除いたもの、字幕は操作と結果だけを説明する。音声付きの旧版は掲載しない。

## コンポーネント
- 任せられる作業は同じサイズのカードで囲わず、成果物へのリンクを含む横線区切りの一覧にする。
- 導入条件は「どこで動くか」「費用は何にかかるか」「データはどこへ送られるか」の3項目で整理する。
- 問い合わせフォームはサイト共通の文字色・境界色・フォーカス表示を使う。送信中はボタンを無効化し、エラー時は入力を保持する既存処理を使う。

## 検証
- 360px、390px、768px、1440pxで横はみ出し、画像・動画表示後のレイアウト、フォーカス、キーボード操作を確認する。
- 通常文字のコントラスト比4.5:1以上を維持する。LCP、INP、CLSは公開後の実利用データで確認し、未測定の値を達成済みとは書かない。
- `demo_start`は動画再生または指摘クリック時、`demo_complete`は動画終了または全指摘確認時、`record_finding`は指摘選択時、`quickstart_copy`はコピー成功時、`contact_submit`はサーバー保存成功時だけ送る。問い合わせ内容は送らない。
