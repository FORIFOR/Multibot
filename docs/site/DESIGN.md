# DESIGN.md — Agent Team site

2026-09-19 改訂。製品UIがキャラクター中心の「Pop Bot Workroom」と3ステップ構成になったため、サイトも同じ見た目と言葉にそろえた。旧方針（白地・朱色・横線区切り・実行記録ビューア）は `git log -- docs/site/DESIGN.md` に残る。

## 方針
- 最初の画面で「頼むのは一度。チームが作って、確かめる。」と、4人のチームが見える。1セクション1主張、見出しは大きく、説明は1〜3文。
- 製品と同じキャラクター（`frontend/src/quiet-cinema.css` の `.bot-*`）を使う。サイト専用の別キャラクターや、製品にない画面は作らない。
- 良い数字だけを並べない。実行記録の partial / 未確認、チームが一人のAIより遅いこと、調べものが苦手なことを、同じ大きさで書く。
- 推薦文、利用者数、スター数、成長率は載せない（実在する根拠がないため）。数字は `docs/evidence/` にあるものだけを使い、各セクションから証跡へリンクする。
- JavaScriptなしで全セクションが読める。スクリプトは、説明用ステージの動き、指摘の切り替え、コマンドのコピー、スクロール時の表示だけを足す。

## 構成（上から）
1. ヒーロー: 見出し、補足、主CTA「自分のPCで始める」、副CTA「実際の記録を見る」、説明用ステージ。1100px以上は左右2カラム。
2. アプリの画面: お願いする・チームを見る・できたものを見る、の実画面3枚（`media/app-*.webp`）。JavaScriptがあればタブ、なければ縦に並ぶ。2と3は実行記録の画面で、日付とモデルを注記する。
3. チーム: まとめ役・調べる係・つくる係・確かめる係。（以下、番号は1つずつ後ろへ）
3. 受け取るもの: ファイル、版の差分、途中の指示、経緯。
4. 実際の記録: 2026-09-13 の実行（`evidence/scenarios/research2`）の指摘 F-1〜F-3。変更前・変更後は `record.js` にある記録の原文をそのまま表示し、要約で置き換えない。結果が partial であることと実測値を直下に置く。
5. 正直な数字: `evidence/local-recompare-2026-09-18` の team / single 比較。限界の一文を必ず添える。
6. データの扱い、7. 始める（コマンド・3手順・対応する接続）、8. よくある質問、9. 最後のCTA、10. 業務利用の相談フォーム、フッター。

## 見た目
- ヒーローと最後のCTAは空のグラデーション（`#22398f`→`#4c69d2`、白文字のコントラスト比4.9以上）、半透明の面、白いボタン。見出しは明朝体（システムの書体。Webフォントは読み込まない）。参考: wonder.next-standards.com の初回案内の空気感。マスコットの意匠は借りず、製品の4人をそのまま使う。
- 本文の面は 背景 `#f7f8ff`、面 `#fff`、本文 `#1d2030`、補足 `#4a5166`、線 `#e2e6f2`、操作 `#4f63d9`。合格は緑、未完了・指摘は琥珀。
- 本文はシステムのゴシック体。H1は36〜74px、H2は30〜56px、本文は16〜17px・行間1.85。見出しは `text-wrap:balance` と `word-break:auto-phrase` で、語の途中で折り返さない。
- カードは角丸26px・線1px。ボタンは高さ48px以上の丸型。最大幅1160px。
- 説明用ステージは「動きを説明するアニメーションで、AIは動いていない」と明記し、止めるボタンを置く。`prefers-reduced-motion` では動かさず、全員を完了の状態で表示する。

## 生成
- `python3 docs/site/build_site.py` が、1つのテンプレートから `docs/index.html` と `docs/ja/index.html` を作る。HTMLを直接直さず、このスクリプトの文言を直して再生成する。

## 検証
- `node frontend/scripts/site-check.mjs <base>`: 日英 × 1440 / 768 / 390 / 360px で、エラー0、横はみ出しなし、H1が1つ、本文16px以上、ボタン48px以上、PCの最初の画面にチームが見える、ステージが動いて止められる、指摘ごとに対応する原文だけが出る、表記・フォーム・コマンド・証跡リンク。加えて reduced-motion と JavaScript 無効。
- LCP、INP、CLS は公開後の実利用データで確認する。未測定の値を達成済みとは書かない。
- 計測イベントは `portfolio.js` の既存の仕組み（`data-track`）だけを使う: `quickstart_open`、`github_outbound`、`artifact_open`、`contact_submit`。
