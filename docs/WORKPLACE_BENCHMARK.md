# Workplace benchmark — 2026-09-13

企業紹介は「役割を分け、成果物をレビュー・改訂して実行記録を残す開発用ランタイム」に限定します。**Single-agentより高品質・低コストという結論はまだありません。** L2の企業内分離・認証・データ保持、L3の可用性・運用はこの試験では認定していません。

## 実行した比較

同じ架空の3社情報から比較表と選定理由を作る1ケースを、同じローカルモデル `qwen2.5:7b` で実行しました。外部調査・送信・有料fallbackなし。

| 条件 | 結果 | 実測時間 | モデル利用 |
|---|---|---:|---|
| 単独のモデル呼び出し | 最低限の出力チェック合格 | 8.716秒 | 1回、input 144 / output 392 tokens |
| Agent Teamランタイム | **partial**、指定ファイル・選定理由が不足 | 169.455秒 | 15回、input 36,858 / output 5,579 tokens |

[実行集計・成果物・イベント](evidence/workplace-20260913/)を参照してください。最低限の検査は指定ファイル・用語・禁止表現であり、人間による正確性/実用性の評点ではありません。今回は計画がmasterだけを選び、複数workerへの分業も発生しませんでした。「多エージェントの優位性」の試験成立とは扱いません。

ランタイムはpartialを表示しましたが、モデルが書いた要約には過大な完了表現が残りました。成果物は `comparison_table.md` で、指定した `comparison.md` はありませんでした。営業資料で成功率や品質向上率に置き換えないでください。

## 修正と失敗履歴

- Ollamaの既定samplingでは接続probeのtool呼び出しが不安定だったため、構造化タスク用のtemperatureを0に固定。probeもpingという名前だけでなく、1回・ok=trueを確認します。
- それ以前の試行1は比較ハーネスのbudget=0設定がschema違反でチームを開始できず、試行2はtool probeが失敗しました。これらは実行済み150件に含めません。[試行履歴](evidence/workplace-20260913/attempts.json)。
- 回帰試験中に、workerが先に停止を観測するとタスクが恒久cancelledになり、再開できない競合を発見しました。run停止をinterruptedとして保存し、既存の完了済み作業を再実行せず復帰するよう修正。競合を決定的に再現する試験を含め **51テスト合格**。
- 最終CIで、完了statusが最終レポートと終端イベントより先に保存される競合も確認しました。レポート・利用量・終端イベントの保存後に完了statusを公開するよう修正。mainの更新を取り込み、レポート処理と終端イベント保存をそれぞれ遅延させる回帰試験を含め **59テスト合格**。上記1組のモデル測定値は再実行で置き換えていません。

## 再現するコマンド

```sh
python3 -m venv .venv
.venv/bin/pip install -e 'backend[dev]'
# 既にインストール済みのOllama qwen2.5:7bを起動する
.venv/bin/python evals/workplace_benchmark.py --out /tmp/agentteam-workplace-new --cases 1 --repeats 1
.venv/bin/python -m pytest backend/tests -q
```

`evals/workplace_benchmark.py`には10カテゴリ×5件の固定合成ケースを収録しています。`--cases 50 --repeats 3`で150回×2方式を要求できますが、今回完了したのは上記1組だけです。3回連続でチームの最低チェックが失敗したら、時間を浪費しないよう停止します。すべて同じモデル/入力を使用し、構成・利用量・時間・成果物hashを記録します。実モデルを呼ぶため電力・計算時間を使用します。外部API料金は0 USD、機器と電力は別です。
