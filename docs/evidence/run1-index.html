一度の依頼で、AIのチームが作業する。
その過程も成果物も、同じ記録に残る。

Agent Team は、Master・Researcher・Builder・Reviewer の4つの役割を持つAIチームが、ひとつの依頼から実際に作業を進めるツールだ。作られた成果物、Bot間でやり取りされた実際のメッセージ、そして時系列を、すべて同じ実行記録から見られる。オープンソースで、ローカルファーストに動く。

「結果だけ出てくる」と、確かめようがない

AIに複数ステップの仕事を任せると、出力は返ってくるが、途中で何を調べ、誰が何を判断し、どのファイルがいつ作られたのかが手元に残らないことがある。レビューのしようがないまま、成果物を信じるか捨てるかの二択になりやすい。

過程が追えない

どの判断がどの調査に基づいたのかが後から辿れないと、間違いの原因も再現できない。

成果物と会話がバラバラ

チャットのログとファイルが別の場所にあると、「この記述はどのやり取りから来たのか」が繋がらない。

役割が混ざる

調べる・作る・確認するが一体になっていると、作った本人が自分の成果物を肯定して終わることがある。

手元に置けない

作業中のコードや文書を外に預けたくない場面はある。実行環境を自分で持てるかどうかは重要な要素だ。

4つの役割が、それぞれの仕事をする

ひとつの依頼を受け取ると、役割の異なるBotが分担して作業に入る。分担されているので、作る側と確認する側が同じではない。

Master

依頼を受け取り、進行を組む

依頼内容を読み、前提の不足を洗い出し、タスクに分けて各役割へ割り当てる。前提を推定した場合は、推定として記録に残す。

Researcher

調べて、根拠を揃える

作業に必要な情報を集め、わかったことと確認できていないことを分けて渡す。

Builder

実際にファイルを作る

受け取った前提と調査結果をもとに実装や文書作成を行い、成果物として残す。何を検証し、何を未検証のまま残したかも添える。

Reviewer

受け入れ条件を実際に確かめる

成果物に対してチェックを走らせ、受け入れ条件を満たしているかを判定する。通らなかった点は、そのまま記録に残る。

成果物・メッセージ・時系列を、同じ実行記録から見る

Agent Team では、生成されたファイル、Bot間で実際に送られたメッセージ、そして各ステップの時系列が、ひとつの実行記録として紐づいている。成果物を開いたまま、それがどのやり取りから生まれたのかを辿れる。

ローカルファーストで、オープンソース

手元の環境で動かす

ローカルファーストな構成なので、実行と記録を自分の手元に置いたまま使える。作業対象のファイルを自分の管理下から出さずに進められる。

中身を読んで確かめられる

オープンソースなので、役割の割り当て方やメッセージの受け渡し、記録の残し方を、実装コードで確認できる。

自分の使い方に合わせる

ソースが手元にあるため、役割やチェックの内容を自分のワークフローに寄せて調整できる。

記録が手元に残る

成果物とメッセージと時系列が同じ実行記録として残るので、後から読み返す、チームに共有する、原因を辿るといった使い方ができる。

想定しているユースケース

ソフトウェア開発者と個人開発者を対象に設計している。以下は想定される使い方の例であり、成果を保証するものではない。

調査から下書きまで一気に

調べる・書く・確認するが分かれているので、調査メモと成果物のどちらも手元に残る。

ひとり開発のレビュー役

個人開発で不足しがちな「別の視点からの確認」を、Reviewer の判定結果として受け取る。

作業の経緯を共有する

実行記録をそのまま共有すれば、結論だけでなく、そこに至る過程も相手に渡せる。

よくある質問

どこで動きますか。
ローカルファーストなツールとして、手元の環境で動かす想定だ。必要な前提条件はリポジトリのドキュメントを参照してほしい。
ライセンスはどうなっていますか。
オープンソースとして公開している。具体的なライセンス条項はリポジトリの記載を確認してほしい。
Bot間のメッセージは編集された要約ですか。
実行記録には、Bot間で実際に送られたメッセージが残る。成果物と時系列も同じ記録から表示される。
4つの役割は変更できますか。
オープンソースなので実装を読んで調整できる。既定では Master・Researcher・Builder・Reviewer の4役割で動く。
導入にかかる費用は。
価格は未定であり、このページでは案内していない。決まり次第、リポジトリとドキュメントで告知する。
どのくらい速く、どのくらい正確ですか。
性能に関する測定値はこのページでは示していない。実行記録に判断とチェック結果が残るため、まずは自分の手元で確かめてほしい。

まずは手元で動かして、記録を見てほしい

出力だけを見て判断するのではなく、誰が何をして、何を確認したのかを含めて読める状態にする。それが Agent Team の狙いだ。
