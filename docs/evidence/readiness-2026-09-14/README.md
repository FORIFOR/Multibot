## Reviewer試験の扱い

[既存結果8行](reviewer-original-results.jsonl)は、A/Bの2文書×3反復と、同じrep=1の先行試行2件です。元の採点はすべて10/10、計80/80でしたが、これは**正規表現への一致数**です。誤記の引用だけでも一致するため、一般的な検出率として広告しません。

今回、反復3の[文書Aレビュー](A-run_1a09a605d17590c3ac0-findings.md)と[文書Bレビュー](B-run_1a09a65f9a060f052d2-findings.md)を読み、元の20採点項目について、誤った記述と正しい値または根拠不足の説明があることを確認しました。人間による独立評価ではなく、今回のエージェントによる文面監査です。他の反復までこの文面監査結果を外挿しません。

さらに、Bの原稿には元の採点対象10項目に入っていない `west 2026-03: 1,340 → 1,430` の誤りがあり、Reviewerはこれも指摘していました。実際にはA10項目、B11項目（うち1項目は出典不足）です。事後に分母を変えて過去のスコアを上書きしません。

制約:

- 実モデルが処理した入力は、既存の合成メモとCSVです。顧客資料ではありません。
- 計画は固定され、Builderには誤りを直さず転記するよう指示しています。通常の「発見→修正→再レビュー」の成功率ではありません。
- 正しい文書だけの対照群がなく、precision / false positive rateは測れません。
- 数字の丸めや出典不足を含むため、検出対象の定義と判定基準を事前固定する必要があります。
- 次回の正式な測定では、箇所・誤記・訂正または根拠不足・参照元を揃えた判定と、未検出・誤検出の両方を記録します。
