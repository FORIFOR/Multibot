実行層が送信元 `source_task_id` を記録し、関連 `task_id` と分離した。成功配送を実行元の引き継ぎへ数える。関連タスクの通信予算、必要宛先、正式レビュー、最新成果物へのレビュー結合、レビュー/再公開後の再配送条件は維持する。旧SQLiteにはnullable列を追加し、旧記録に送信元を推定して書き込まない。[契約と再現手順](../../quality/message-handoff-provenance.md) を参照。

実v62の原引数・原成果物・原イベントから実SQLite/EventStore/MessageBus/ToolGatewayへ再生した。実装担当と独立担当の両実行で12項目PASS。新規LLM呼出・サービス起動は0で、終了時に元資料hashの不変を確認した。元schemaの実Git objectを使うDB移行、JSON/HTTP投影、再接続、予算拒否、無効宛先、レビュー前の配送リセットも含む。各JSONのcode_headは変更前HEADを指し、検証した未コミット実装はcode_sha256で識別する。
