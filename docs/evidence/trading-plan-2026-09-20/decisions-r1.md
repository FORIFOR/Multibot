# 株式トレードアプリ 設計決定事項

## 1. 決定済みの事項

### 1.1 システム構成
- **Core**: 注文状態管理、状態機械、重複防止、エラーハンドリングの中枢
- **証券 Adapter**: 各証券会社の API へ接続し、注文・市場データ・口座情報を抽象化
- **UI**: ユーザー向け画面、価格取得時刻・利用権限表示

### 1.2 境界線
- Core ↔ 証券 Adapter: Adapter が `Order`, `OrderStatus`, `MarketData` を提供
- Core ↔ UI: Core が WebSocket 接続を管理し、UI へ `trade_update` をストリーミング
- 証券 Adapter ↔ 外部 API: 認証は OAuth2 または API キーペア、秘密鍵はサーバー側管理

### 1.3 認証認可
- ユーザー認証: OAuth2 または API キーペアのいずれか
- 証券 API キーはサーバー側管理
- ブラウザへ秘密鍵を渡さない

### 1.4 注文状態管理
- 状態機械: `pending` → `partial_fill` → `fill` / `canceled` / `rejected`
- `pending_cancel`: 取消待ち（取消完了ではない）
- 部分約定と取消競合は状態機械で管理し、UI と同期
- 重複防止: サーバーサイド idempotency key とクライアント側 `client_order_id` 管理の組み合わせ

### 1.5 エラーハンドリング
- 応答喪失時の再接続: Exponential backoff を使用
- 再接続後に、口座・注文・約定を照合
- エラー分類: 一時的エラー（再試行）、永続的エラー（UI へ表示）

### 1.6 画面構成
- 口座情報画面（Live/Paper 切り替え、残高、利用権限）
- 注文画面（銘柄、数量、注文タイプ、価格条件）
- 約定履歴画面（部分約定・完全約定・取消）
- 市場データ画面（取得時刻付き）
- 利用権限表示: 画面に「利用権限: あり/なし」を表示
- 価格取得時刻: 「取得時刻: YYYY-MM-DD HH:mm:ss」で表示

### 1.7 実装段階
- **Paper 環境での実装**: WebSocket 接続、注文フロー、状態同期の検証
- **Live 環境への拡張**: API キー切り替え、本番接続テスト、本番取引開始（権限確認・検証通過後）
