# 初回接続失敗からの復帰観察（未修正候補）

2026-10-02 JST、独立した AI 検証担当が実 AppService と Google Chrome を使って観察しました。**初回の認証 API 通信が失敗すると、画面に再読込の説明は出ますが、ページ内の再試行操作はありません。通信を復旧して 5 秒待ってもログインは無効のままでした。ブラウザーの再読込でフォームは復帰し、実発行した技術 operator キーでログインできました。** 製品コードは変更していません。

実資料の保存済み v61 構成を新規私有 SQLite に設定し、JA 390×844 では `/api/auth/status`、EN 768×844 では `/api/auth/me` の初回要求を Chrome CDP `Network.setBlockedURLs` で遮断しました。画面や API 応答の差替えはなく、実通信の失敗・遮断解除・ブラウザー再読込を観察しています。解除後は 5 秒の範囲で追加 API 応答 0、エラー表示と無効なログインが継続しました。再読込後の実 `/api/auth/status` 200・未認証 `/api/auth/me` 401、ログイン 200、再認証後の主体・権限一致を確認しています。

初回 r1 はブラウザー再読込を `networkidle` で待つ検査側の上限超過により FAIL でした。その時点でも実 status 200 / me 401 が届いており、製品の再読込失敗とは判定しません。原 FAIL を [r1-failed-observation.json](r1-failed-observation.json) として保持しました。r2 では `DOMContentLoaded` と実フォーム状態の待機へ限定し、同一の配信 UI バイトで日英 2 条件を完了しました。インストール済み Chrome の実バージョンは r1/r2 で異なるため、両値を保持しています。
