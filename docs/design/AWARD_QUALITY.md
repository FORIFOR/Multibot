# 公開サイトと製品の品質を継続して磨く

2026-10-02 のユーザー指示: Awwwards、Webby Awards、FWAで受賞を狙える完成度を目標とし、セルフチェックと改善を繰り返す。これは新しいデザインブランドへの変更、架空の実績の追加、受賞の保証ではない。一般公開サービス化の受入条件は [PUBLIC_SERVICE.md](../PUBLIC_SERVICE.md) に残す。

## 参照した公式基準

- [Awwwards](https://www.awwwards.com/about-evaluation/): Design 40%、Usability 30%、Creativity 20%、Content 10%。外部審査の配点であり、自分で閾値を作って受賞相当と判定しない。
- [Webby 2026/2027](https://www.webbyawards.com/judging-criteria/): 内容、構造とナビゲーション、視覚、機能、対話性、革新性、総合体験。アクセシビリティ、速度、実際に機能する技術、AIの誠実な利用も見る。
- [FWA](https://thefwa.com/FWA25/25.html): デジタルの革新、創造性、独創性、技術的完成度。今回の一次資料では軸別の正式配点は未確認。

公式資料は2026-10-02に調査担当が読み取り確認。以下の実装上の判定項目は本プロジェクトの基準であり、各賞の公式合格点ではない。

## 今回の方向

既存の紙色、墨色、赤い主操作、役割ごとの形キャラクターを維持する。考えた方向は次の3つ。

1. 旧動画を中心にしたシアター: 動画を見れば作業を追えるが、モバイルの細かい文字と現在のアプリとの違いが残る。
2. キャラクター中心の舞台: 親しみは出るが、AIが実行中という錯覚や、装飾のための動きに寄りやすい。
3. **実記録を読める紙の作業台（採用）**: 指摘を選び、保存された前後の文面と未確認事項へ直接つながる。キャラクターは役割を伝え、主役は実際の成果物と判断材料にする。

内容の正本は公開サイト `docs/site/copy.json`。構造は `docs/site/build_site.py`、表面は `docs/home.css`。前後の抜粋は `docs/evidence/scenarios/research2/research.md.r1` と `research-final-r2.md.r1` から生成時に抽出し、編集者が成功文へ書き換えない。英語ページでも原文は日本語と明示する。旧比較の合成課題の数値は新しい公開品質の説明に使わない。

## 反復ごとの証拠

| 観点 | チェック | 達成扱いにしないもの |
| --- | --- | --- |
| 視覚 | 同じ実資料で1440/768/390/320幅、構図・文字・余白・ブランドの統一を画像レビュー | 自己採点、画像を見ない自動検査だけ |
| 内容 | できること・利用開始方法・未提供/未確認を初見で理解できるか。抜粋の原文とSHAを照合 | 架空の成果や成功表示、旧合成比較の実務への一般化 |
| 操作 | キーボード、資料添付/貼付、入力保持、実記録選択、確認、版の採用と保存 | ボタンの表示だけ、採用＝品質合格 |
| アクセシビリティ | コントラスト、フォーカス、200%文字拡大/リフロー、reduced motion、JSなしの公開本文 | axe違反0＝全面適合、デスクトップChrome＝実iPhone |
| 性能 | 実Chrome・条件・コードhashとnavigation/LCP/CLS/転送量を残す | localhostの測定＝実利用者のp75や速度保証 |
| サービス | 実IdP/TLS/登録/復旧/監視/利用枠、実資料による業務の正確さ | 見た目の改善＝本番化/人間受入/受賞 |

各回で、変更前の証拠→欠点→修正→同条件の再確認→別担当による批評を残す。主要工程の消失・誤認・データ漏れ・横スクロール・押せない主要操作は装飾の評価と相殺しない。新しい指摘が残る場合は改善を続け、未測定は未確認と記す。AIによる独立レビューは人間の初見利用試験ではない。

2026-10-02の[認証状態の接続回復](../evidence/auth-connection-recovery-20261002/README.md)では、実通信遮断で観察した行き止まりへ、画面内の明示的な再読込操作を追加した。日英・小画面・実200%と既存peer境界を独立に操作し、ログイン未確認の欄を取り除いた。認証済みタブの再表示を試す追加観察は前提未成立として原FAILを保持し、成功に数えない。

2026-10-02の[中間幅の見出しと再開注意書き](../evidence/tablet-reading-craft-20261002/README.md)では、実768幅で狭まった依頼名を全幅にし、別担当が実200%で見つけた確認ボタンの見切れを次の反復で修正した。縦方向に長くなる条件や原失敗も保持する。[運用画面](../evidence/operations-readiness-craft-20261002/README.md)は実応答と認証構成に合う案内へ修正し、[初回接続失敗の原観察](../evidence/auth-initial-recovery-observation-20261002/README.md)は当時の未修正状態を保存する。

2026-10-02の[小画面ナビゲーションの反復](../evidence/mobile-navigation-craft-20261002/README.md)では、新しいお願い・一覧を常設し、言語・主体・管理操作を開閉できるようにした。同じ未採用記録のメニュー高153→107pxを実測し、4ロール・履歴・下書き・実200%を独立確認した。768幅の見出し、入力欄下端、進行/問題/再接続などの残る観察を次に進める。公開画像のスクロール位置を整えたことと、製品不具合の修正は分けて記録する。

2026-10-02の[小画面の読取り反復](../evidence/mobile-reading-craft-20261002/README.md)では、終了結果の担当者一覧を開閉できるようにし、本文前の重複説明を整理した。同じ実記録の前後画像と独立操作を保存し、実200%で観測した一部隠れたfocusへの追従も別に修正した。文字の縮小や未完了警告の削除で前置きを短くしない。画面の短縮量や確認項目数は受賞水準の判定に使わない。

初回の[公開サイト・依頼画面の実測と反復](../evidence/award-craft-20261002/README.md)を保存した。`frontend/scripts/site-quality-audit.mjs` で実Chromeの公開ページ回帰をCIでも確認する。サイトのチェック通過だけで、依頼から保存までの全製品評価を終了しない。

次の[資料追加・一覧・成果物の確認と採用/保存の反復](../evidence/result-reading-craft-20261002/README.md)では実v62記録を新しいSQLiteへ取り込み、本文より先に並ぶ操作とキーボードの確認経路を修正した。原記録、未検証のOS取消・複数版/ファイル状態、業務品質未達を保持する。
