# Agent Team アプリ — 受け入れ基準

数値はこのプロジェクトで合意する基準で、他社との比較結果ではない。
「壊れていない」「見た目が整っている」「他社より優れている」は別々に扱い、別々に報告する。

## 1. 主タスク
- Given 接続が確認済みのチーム / When 入力欄に書いて「チームにお願いする」/ Then 作業の画面に移り、チームの状態とやりとり、できたファイルが同じページに出て、「この版を使う」で選べる。
- 二重送信で依頼が2つ作られない。書きかけの追加指示が、ページ内の移動で消えない。読み取り専用の利用者には実行ボタンが出ない。
- 承認待ちは、どの場所を見ていても見える。押すまで決定は送られない。
- 機械で確かめる場所: `three-step-smoke.mjs`、`ui-polish-smoke.mjs`、`ui-smoke.mjs`、`workroom-smoke.mjs`。

## 2. 画面幅と内容
- 390 / 768 / 1100 / 1440px で意図しない横スクロールがない。
- 1440×900 で、できたものの読み物が最初の画面に入る。成果物の表示幅は650px以上。
- 長い日本語のお願い（100字超）、0件・1件・複数のファイル、やりとり0件、未完了、問題のある接続を確認する。
- スマホ幅のChromeでの確認と、実機のiPhoneでの確認を別に書く。

## 3. アクセシビリティ
- 通常の文字は4.5:1以上、大きい文字は3:1以上。
- 押せるものは高さ44px以上を目標にする（WCAG 2.2 AAの最低値ではなく、このプロジェクトの目標）。
- キーボードで主タスクを完了できる。フォーカスが見える。開いたフォームはフォーカスを中へ移し、その移動をテストが待つ。画面が入れ替わったら、新しい画面の見出しへフォーカスを移す（`journey-capture.mjs` が順序と移動先を記録する）。
- 状態は色だけで示さない（バッジの記号、状態の文字）。
- 自動検査（`frontend/scripts/a11y-smoke.mjs`、axe、WCAG 2.x A/AA、4画面×日英×2幅）で0件でも、適合とは書かない。成果物のプレビュー（sandbox付きiframe）は検査の対象外で、人が確認する。

## 4. 見た目の方向
- 視線が、状況→できたもの、の順に向かう。キャラクターは状態が読める大きさで、常に見える。
- 日常の画面に内部用語を出さない。詳しい作業記録の中は例外。
- 飾りを足す前に、情報を減らす。

## 5. 動きと反応
- 押したあとの反応、読み込み中、完了、失敗への移り変わりを実画面で見る（`journey-capture.mjs` が通信を保留・中断して撮る。自動撮影は人の確認の代わりにはならない）。
- reduced-motion と「動きを止める」で、本質でない動きがすべて止まる。通常の動きは別に確認する。
- 速さは、測った環境と方法と数値を書く。測っていないものを速いと書かない。

## 6. 完了
- 最新のコードで、テスト・画像・独立レビューがそろっている。P0/P1が残れば未完了。
- 未実施の確認をPASSにしない。報告は「機械テスト」「AIによる画像レビュー」「人の承認」「利用者による確認」を分けて書く。
- 基準画像を使う場合は、人が承認してから保存する。
